## 1. What This Project Is

A Streamlit dashboard for the Colombian bond trading desk at **Pina Colombiana**, deployed on Streamlit Community Cloud. It ingests the BVC (Bolsa de Valores de Colombia) daily fixed-income bulletin (`BoletinDiario_*.xlsx`) and provides analytical views of **BGLT bonds** (Public External Debt Bonds, USD-denominated).

**Live URL:** https://trading-bolsa-col-zqt8cbw7elgkwdfc3blntx.streamlit.app  
**Repo:** https://github.com/dfsosa83/trading-bolsa-col

## 4. Data Sources

### 4.1 BVC Bulletin (primary)
- **URL pattern:** BVC Hygraph GraphQL API at `https://us-east-1-bolsa-co.cdn.hygraph.com/...`
- **Auth:** Static Bearer token embedded in `download_bvc_daily.py` (issued Dec 2021, public)
- **Format:** ZIP containing a single `.xlsx` (BoletinDiario_YYYY_MM_DD.xlsx)
- **Sheets used:**
  - `RF-Mercado Secundario` — bond-level stats. Key columns per bond:
    - `cv_monto` — Compra-Venta (outright) notional (M COP)
    - `sim_monto` — Simultáneas (repo) notional (M COP)
    - `cv_num_opes` — number of CV operations
    - `cv_tasa_cierre/min/max` — closing/min/max yield (% e.a.)
  - `RF-PorTipoInver` — sector-level totals (AFP, Fiduciarias, Extranjeros, etc.) per instrument type. **Includes both CV + SIM** in the reported amount.
- **History:** 14+ bulletins stored in `data/history/`, automatically grown by GitHub Actions.

### 4.2 TRM (USD/COP rate)
- **Source:** `https://www.datos.gov.co/resource/32sa-8pi3.json?$limit=1&$order=vigenciadesde+DESC`
- **Fallback:** 4,000.0 COP/USD if API unreachable
- **Cache:** 1 hour

### 4.3 SFC Pension Fund Holdings (AFP data)
- **Primary:** `data/sfc_portafolio/bglt_holdings.csv` (generated by `scripts/download_sfc_portafolio.py`)
  - Columns: `fecha, entidad, fondo, nemotecnico, moneda, valor_cop`
  - Coverage: Jan–May 2026 (6-month lag from SFC publication)
  - Only Colfondos and Porvenir have BGLT holdings; Protección/Skandia have none
- **Fallback:** `https://www.datos.gov.co/resource/ur2p-h4yf.json` (Formato 351)
- **Cache:** 24 hours

## 5. App Structure — Five Tabs

### Tab 1: 📅 Vista Diaria
- Sidebar: date selector (history files + live API), TRM display
- Bond table: BGLT bonds with CV Monto, Monto USD (calculated via TRM), yields
- Buyers/sellers table: sector breakdown from RF-PorTipoInver
- Download button: full Excel report (`generate_to_bytes()`)

### Tab 2: 📈 Posiciones Históricas
- Line chart: daily net position per sector (M COP)
- Altair heatmap: sector × date grid, color = net position (red/yellow/green, domainMid=0)
- Cumulative bar chart
- Data source: all `data/history/*.xlsx` files via `_build_history_df()`

### Tab 3: 📉 Curva de Tasas
- Snapshot yield curve for selected date (scatter + line, x=maturity years, y=rate)
- Rate evolution over time (line chart per bond nemo)
- Latest rates table
- Data source: `_build_yield_history_df()` — only bonds where `cv_tasa_cierre > 0`

### Tab 4: 🏦 Fondos de Pensiones
- AFP holdings from `bglt_holdings.csv` (or API fallback)
- Line chart: evolution of holdings per AFP
- Pie: composition by bond at latest date
- Bar: distribution by fund type
- Detail table: bond × fund breakdown
- Data source: `_get_pension_bglt()`

### Tab 5: 🔀 Triangulación
Three sub-sections (see §6 for full algorithm detail):
1. **🎯 Cruces Identificados** — exact-match (sector_buy ≈ sector_sell) with bond subset-sum
2. **🧩 Atribución Completa** — backtracking zero-sum solver
3. **📊 Modelo Proporcional** — full flow matrix (proportional model, covers 100% of volume)
4. **🏆 Cruces Más Probables** — top flows from proportional model for selected date
5. **🔁 Patrón Histórico** — average flows across all history; identifies structural crosses

## 6. Triangulation Algorithm (Critical Logic)

This is the core intellectual contribution of the project. The desk uses it to identify who traded with whom.

### 6.1 Why Triangulation Is Needed

The BVC bulletin only shows:
- **Per bond:** total monto bought + sold (but NOT counterparties)
- **Per sector:** total bought + sold per instrument (but NOT which bonds)

The desk needs to reconstruct: **which sector bought/sold which bond with whom**.

### 6.2 Key Domain Constraint (MANDATORY)

> **Extranjeros → Extranjeros = 0**

Foreign entity ↔ foreign entity operations bypass BVC local registration and never appear in the bulletin. All three models must enforce this. This is stored in `/memories/repo/trading-bolsa-col-constraints.md`.

### 6.3 Model 1 — Proportional Flow Matrix (`_flow_matrix`)

Entropy/independence model:
```
F[buyer][seller] = (buy_buyer / total) × sell_seller
```
Applied after zeroing Ext→Ext and redistributing Ext seller flows proportionally among local buyers only.

**Covers 100% of volume. No bond-level resolution.**

### 6.4 Model 2 — Exact-Match Identification (`_triangulate_with_bonds`)

For each (buyer, seller) pair:
1. Find pairs where `|buyer_total - seller_total| ≤ 1.5%`
2. For matching pairs, run subset-sum over bond montos to find which bond(s) produced that amount
3. Uses `_monto_raw` (CV+SIM total) for matching, shows CV monto in display

**Greedy (largest first). Marks sectors as "used" once matched — misses multi-pair sectors.**

### 6.5 Model 3 — Complete Attribution Backtracking (`_find_complete_attribution`)

**Desk's key insight:** `sum(bond_montos) = sum(sector_buys) = sum(sector_sells)` — zero-sum. So a valid complete assignment always exists (unless Simultáneas distort the totals beyond tolerance).

Algorithm:
1. Sort bonds largest-first (best pruning)
2. For each bond, try every valid `(buyer, seller)` pair; reduce budgets; recurse
3. **Critical extension for multi-op bonds (`# Oper. >= 2`):** also try splitting the bond into two equal halves assigned to *different* pairs — this is exactly how BGLT32180141 works (Fiduciarias→Extranjeros "1 de 2 op." + Extranjeros→Fiduciarias "2 de 2 op.")
4. Solution found when all bonds assigned AND all sector budgets exhausted (within 2% tolerance)
5. Returns up to 3 solutions; labels split bonds as "1 de 2 op." / "2 de 2 op."

**Uses `_monto_raw = cv_monto + sim_monto`** because RF-PorTipoInver sector totals include Simultáneas. Using CV-only caused the zero-sum to fail (gap ≈ SIM volume).

When no solution found, shows diagnostic:
```
Bonos (CV+SIM): 203,529 M COP · Compras sectoriales: 220,000 M COP · Diferencia: +16,471 M COP
Probable causa: Simultáneas en los totales sectoriales no reflejadas en los bonos CV.
```

## 8. Deployment — Critical Notes

### Streamlit Community Cloud runs Python 3.14
- `runtime.txt` (contains `python-3.12`) and `.python-version` (contains `3.12`) are both **ignored**
- The only way to change Python version is via Streamlit Cloud Settings UI → Python version dropdown
- Altair 5.5+ is broken on Python 3.14 — **`altair<5.5` must not be changed**

### Error handling architecture
The entire app is wrapped in a top-level `try/except`:
```python
try:
    _main()
except Exception as _top_exc:
    st.error(f"⚠️ App error ({type(_top_exc).__name__}): {_top_exc}")
    st.code(traceback.format_exc())
```
Each of the 5 tabs is additionally wrapped in `_safe_tab(tab)` context manager that catches per-tab errors and displays the traceback inline, preventing a single broken tab from crashing the whole app.

### GitHub Actions
- Runs `scripts/download_history.py` daily at ~8:15am COT
- Downloads the most recent BVC bulletin to `data/history/`
- Idempotent (skips if file already exists)
- History files are committed to the repo, making them available on Cloud

## 9. Data Flow

```
GitHub Actions (daily)
  └─ scripts/download_history.py
       └─ BVC Hygraph API → data/history/BoletinDiario_YYYY_MM_DD.xlsx

Streamlit App Load
  ├─ history_files = glob(data/history/*.xlsx)        # local files
  ├─ api_map = _get_reports()                          # live API (last ~3 bulletins)
  ├─ all_dates = merge(history_files, api_map)
  │
  ├─ User selects date
  │    └─ _parse(xlsx_bytes)
  │         ├─ rf_mercado_secundario.parse() → bond_df (+ _monto_raw = cv+sim)
  │         └─ rf_por_tipo_inver.parse()     → buyers_df, sellers_df (CV+SIM totals)
  │
  └─ Tabs render with cached data
       ├─ tab_hist/yield/cross: _build_history_df / _build_yield_history_df
       └─ tab_pension: _get_pension_bglt() → data/sfc_portafolio/bglt_holdings.csv
```
